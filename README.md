# Click & Co

Click & Co is a **private agency platform**, not a public SaaS. There is no
self-service sign-up. Only the Super Admin (the agency operator) creates and
configures **Companies** — separate, fully isolated client systems, each with
its own branding, modules, users, and data. Company Admins and Staff log into
the branded system that was built for them; they cannot create companies,
see other companies' data, or change the underlying platform.

> "I log in as Super Admin → I create a company → I design that company's
> system (Build Mode) → I add their staff → the company logs into its own
> branded portal and uses the system I built for them."

## Stack

- **Framework**: Next.js 16 (App Router, Turbopack) + React 19 + TypeScript
- **Styling**: Tailwind CSS v4 (brand tokens in `src/app/globals.css`)
- **Database**: PostgreSQL + Prisma 7 (driver adapter: `@prisma/adapter-pg`)
- **Auth**: Custom DB-backed sessions (httpOnly/secure/SameSite cookies), bcrypt password hashing, TOTP + email 2FA, CSRF via double-submit cookie
- **Email**: nodemailer over SMTP; falls back to console logging in dev when no SMTP is configured
- **File storage**: local disk under `/public/uploads` by default; swappable for S3-compatible storage (see `src/lib/storage`)
- **Automation canvas**: `@xyflow/react`; charts: Recharts; drag-and-drop: `@dnd-kit`

Next.js 16 has meaningful breaking changes from older training data (async
`params`/`searchParams`/`cookies()`, `proxy.ts` instead of `middleware.ts`,
Turbopack by default). See `AGENTS.md` and `node_modules/next/dist/docs/` —
that block is regenerated by `next dev`, don't remove it. Likewise Prisma 7
requires an explicit driver adapter and generates its client to
`src/generated/prisma` (gitignored) — see `.claude/skills/prisma-*` for the
current CLI/Client API.

## Architecture

- **Identity**: one `User` table for everyone (Super Admin, Company Admins, Staff). `User.platformRole` marks the Super Admin; `Membership` links a user to a `Company` with a `CompanyRole` (`ADMIN` | `STAFF`) and, for staff, an assignable `StaffRole` carrying a per-module permission matrix (view/create/edit/delete/export/assign/approve/settings).
- **Multi-tenancy**: every tenant-scoped table carries `companyId`. All reads/writes go through `loadCompanyContext()` / `requireApiCompanyContext()` (`src/lib/auth/rbac.ts`, `src/lib/api-guard.ts`), which resolve the caller's active company from their session and enforce permissions — there is no code path that lets one company read another's data.
- **Super Admin "enter company"**: `Session.activeCompanyId` + `Session.impersonatedByUserId` let the Super Admin switch into any company's portal (reusing the exact same `/portal` UI staff see) without a separate parallel codebase, fully audit-logged.
- **Build Mode (the core feature)**: `CompanyModule` + `ModuleField` + `ModuleRecord` implement a genuine no-code custom-entity builder — the Super Admin defines arbitrary modules (e.g. "Properties", "Vehicles") with typed fields per company; records are stored as JSON keyed by field, so no per-tenant schema migrations are needed. `DashboardWidget` and `CompanyModule.sortOrder`/`group` drive the per-company dashboard and sidebar builders.
- **No public signup, no courses, no funnels/page-builder, no e-commerce**: intentionally out of scope for this product — see the top of `prisma/schema.prisma`.

## Getting started

```bash
cp .env.example .env   # fill in DATABASE_URL at minimum; see below
npm install
npx prisma migrate deploy   # apply migrations
npx prisma db seed          # creates the Super Admin + sample company + public site content
npm run dev
```

Required env vars (see `.env.example` for the full list with generation
commands):

- `DATABASE_URL` — PostgreSQL connection string
- `SESSION_SECRET`, `ENCRYPTION_KEY` — server-only secrets (never exposed to the client)
- `SUPER_ADMIN_EMAIL` / `SUPER_ADMIN_PASSWORD` — read **only** by `prisma db seed`, hashed immediately with bcrypt, never stored or read in plaintext again. The seeded account has `mustChangePassword = true`, so the first login forces a password change.

Everything else (SMTP, manual billing, S3) is optional in development — the
app runs correctly without them, using safe fallbacks (email logs to the
console, local disk storage).

## Project layout

```
prisma/schema.prisma       Full data model (see section comments)
prisma/seed.ts             Super Admin + sample company + public site content
src/lib/                   Core server logic: auth, RBAC, mail, storage, permissions, company provisioning
src/components/ui/         Shared UI kit (brand-styled, no external component library)
src/app/(marketing)/       Public marketing site
src/app/admin/             Super Admin control centre
src/app/portal/            Per-company branded workspace (Company Admin/Staff + Super Admin "entered" view)
src/app/api/                Route handlers (REST-ish JSON API used by client components)
src/proxy.ts                Lightweight route protection (Next 16's `middleware.ts` successor)
```
